# 揭棋专用棋谱与隐私回放设计

## 目标

揭棋棋谱必须在任意回放时刻维持实战中的信息边界：

- 未移动的暗子身份只属于裁判态，红方、黑方和观众都不能提前得知，包括本方暗子。
- 暗子移动后，移动棋子的真实身份成为公开信息。
- 暗子被吃时，真实身份只对捕获方可见；另一方和观众只知道一枚暗子被吃。
- 普通象棋棋谱、研究、分析、变招树、训练题和分享链接不能读取揭棋私有数据。

因此揭棋记录不复用普通 FEN、`MoveRecord`、变招树或普通游戏 JSON。现有本机揭棋存档中的完整暗子布局只用于恢复正在进行的对局，属于裁判态，不是可分享棋谱。

## 三层模型

### 公开层

公开层可以提供给观众，也是一切默认分享的唯一来源：

- 初始棋盘只保存暗子的颜色和原位走法 `movementType`，不保存真实身份。
- 每步只保存走棋方、起点、终点、当步公开的移动棋子身份和公开吃子状态。
- 被暗吃时只保存 `covered + color`，不保存真实身份。
- 不复制旧 `MoveRecord.notation`、备注、FEN 或快照；旧记谱可能包含“获 R”一类席位私有信息。

### 席位私有层

红、黑两方各自只有一条追加式私有事件流：

- 仅在该席位捕获暗子时记录 `ply + capturedColor + capturedType`。
- 红方投影不含黑方私有事件，黑方投影不含红方私有事件。
- 席位投影不含完整初始身份，也不会因为是“本方棋子”而提前公开身份。

本机第一阶段只持久化执棋者本人的席位投影。它不能升级为裁判投影，也不能用于推导另一席位的私有事件。

### 裁判层

裁判层保存完整初始暗子身份，负责从实战状态生成前两层数据：

- 仅存在于受保护的本机对局存储，或未来局域网房间服务端。
- 不写入浏览器揭棋记录库。
- 不经过普通导入、导出或分享接口。
- 只能通过字段白名单投影，禁止对象展开、删字段后返回或提供 `includePrivate` 开关。

## 投影矩阵

| 数据                 | 观众/公开 | 红方   | 黑方   | 裁判 |
| -------------------- | --------- | ------ | ------ | ---- |
| 公开初始暗盘         | 可见      | 可见   | 可见   | 可见 |
| 已移动暗子的公开身份 | 可见      | 可见   | 可见   | 可见 |
| 红方暗吃所得身份     | 不可见    | 可见   | 不可见 | 可见 |
| 黑方暗吃所得身份     | 不可见    | 不可见 | 可见   | 可见 |
| 未揭晓的初始真实身份 | 不可见    | 不可见 | 不可见 | 可见 |

投影函数逐字段新建对象。即使裁判态未来增加调试字段、备注或新类型，旧投影也不会自动携带。

## 回放规则

回放只接受 `JieqiRecordProjection`，并从公开初始暗盘逐手向前重建：

1. 第 0 帧所有暗子只有 `movementType`；只有裁判投影内部可关联真实身份。
2. 暗子首次移动时，事件必须包含公开揭晓身份，落点从暗子变成明子。
3. 明子再次移动时不得重复携带揭晓身份。
4. 公开吃子信息必须与当时落点棋子状态一致。
5. 席位私有暗吃事件必须与同一手公开事件、捕获方和被吃颜色一致。
6. 每步必须通过揭棋规则合法走法校验，结构正确但无法实战走出的导入会被拒绝。
7. 每一帧都深拷贝；后续事件不能反向改变早期帧，UI 也不会在当前手之前展示未来公开事件的揭子详情。

这条路径不调用普通 FEN 解析、研究回放、历史快照或引擎分析，避免通过兼容逻辑读取未来信息。

## 存储与导出边界

- 本机记录库只接受 `audience: red | black` 的席位投影，拒绝公开投影冒充本人记录，也拒绝裁判投影。
- 读取本地数据时按字段白名单重建，并完整正向回放一次作为语义校验；损坏记录不会进入 UI。
- 默认导出生成公开投影，内容不得出现 `privateEvents`、`capturedType` 或裁判初始身份。
- 本人私有备份使用独立 envelope、MIME/扩展名和视觉警示，导出前必须二次确认。
- 普通 `xiangqi-games.json` 全量导出过滤揭棋；显式选择揭棋时直接报错。普通导入拒绝带裁判态的揭棋游戏。
- `/api/games` 只允许回环 socket、回环 Host，以及开发代理覆盖写入的回环原始客户端地址，阻止局域网监听和伪造 Host 旁路读取本机裁判态。

## 分阶段实施

### 第一阶段：本机本人视角

- 已结束的本机揭棋对局生成执棋者席位投影并保存在浏览器。
- 独立记录库和只读回放页始终标注“本人视角 · 红方/黑方”。
- 公开导出与本人私有备份分别处理；不开放分析、变招、训练或普通分享入口。

### 第二阶段：局域网记录

- 已完成。房间服务端保留裁判态，终局快照按当前 WebSocket 的鉴权角色分别生成红方、黑方或观众投影。
- 恢复席位后只能取得该席位投影；错误凭据、未入座房主和观众只能取得公开投影。
- 服务端不提供由客户端选择 audience 的下载接口；浏览器席位只保存本人投影，观众公开投影只在结果页临时回放。
- 服务重启后从持久化裁判态正向重演投影，不持久化三份可漂移的派生副本。

第二阶段 UI 已在跨视角、双方暗吃、重连与服务重启门禁测试通过后开放。

## 发布门禁

- 红方、黑方、观众和裁判对同一事件流逐手回放，比较每一帧的可见身份。
- 同时覆盖双方暗吃，确认身份只进入捕获方投影。
- 序列化扫描公开投影和普通导出，禁止出现初始身份、`capturedType`、私有记谱哨兵或未来新增字段。
- 损坏、越权或跨席位私有事件必须在载入时拒绝。
- 局域网阶段增加断线、重连、换设备恢复和服务重启后的跨视角测试。
- 每次发布继续运行普通象棋导入导出测试，确保隔离改动不影响普通棋谱。

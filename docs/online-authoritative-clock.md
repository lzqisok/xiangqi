# 公网服务端权威棋钟

权威棋钟同时服务休闲公网对局和排位匹配。无棋钟对局继续沿用原流程；排位必须显式选择棋钟，并按[公网排位等级分策略](online-rating-policy.md)结算。

## 档位与计时规则

| 档位      | 基础时间 | 每步加秒 | 延时 |
| --------- | -------: | -------: | ---: |
| `10m`     |  10 分钟 |        0 |    0 |
| `15m-10s` |  15 分钟 |    10 秒 |    0 |
| `30m`     |  30 分钟 |        0 |    0 |

- 等待就座和双方准备期间不计时；双方准备完成后红方棋钟启动。
- 服务端收到合法落子命令时扣除当前行棋方耗时，完成落子后才增加 increment，再启动对方棋钟。
- 断线、重连、后台标签页和协商期间棋钟继续运行；原有掉线宽限判负仍可更早结束对局。
- 设备时间不参与裁决。客户端只使用服务端快照和本地单调 elapsed time 做显示估算。
- 悔棋不返还已消耗时间；接受悔棋时把计时权切换到回退后局面的行棋方。

## 持久化、重启与竞态

裁判态持久化双方剩余毫秒数、当前行棋方和绝对截止时间。单次进程运行期间，以启动时的 wall clock 为锚点并用 `performance.now()` 的单调 elapsed time 生成裁决时间，避免运行中校时导致棋钟跳变；进程内定时器只负责及时触发。重启后从数据库恢复 active match 并按持久化截止时间重新调度，因此内存定时器不是事实来源。

落子、超时和其他终局都沿用 match revision 的乐观并发控制并在同一数据库事务更新 `matches` 与 `match_states`。截止点之后到达的落子会直接提交超时结果；定时器与落子同时竞争时，只有先取得当前 revision 的事务能生效，另一方重新读取权威快照。

揭棋、普通象棋和五子棋共用棋钟壳；各自合法着、终局判断和揭棋私有裁判态仍走原有隔离规则。公开大厅摘要不包含实时棋钟，订阅对局后才返回当前投影。

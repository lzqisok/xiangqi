# 公网平台威胁模型与部署基线

## 状态与范围

本文覆盖首个公网账号在线版本的攻击面、控制措施、部署拓扑、秘密管理、备份恢复和发布门禁。它不宣称解决大规模 DDoS、完整反作弊、多区域容灾或所有运营合规问题。

受保护资产：

- 账号凭据、会话和恢复 token。
- 用户私有对局、研究、训练、残局、设置和导出。
- 在线对局席位、权威走法、结果和未来等级分。
- 揭棋红/黑席位私有信息和完整裁判态。
- 聊天、举报证据和安全审计。
- MySQL、邮件服务、引擎进程和部署密钥。

信任边界：

- 浏览器和所有客户端输入均不可信。
- 反向代理只在明确网络范围内可信。
- Node 应用是公网请求进入 MySQL 和引擎的唯一业务入口。
- MySQL 应用角色不是管理员，不拥有 migration/backup 权限。
- Pikafish/Rapfi 是受资源约束的本地进程，不接触数据库凭据或用户账号。
- 管理员也不默认拥有揭棋裁判数据读取权。

## 目标部署拓扑

```text
Internet
   │
   ▼
DNS / 基础流量防护
   │
   ▼
TLS Reverse Proxy
   ├─ HTTPS 静态资源
   ├─ HTTPS /api/*
   └─ WSS /ws, /gomoku-ws
          │ 仅可信代理网络
          ▼
Node.js 单实例
   ├─ Express HTTP
   ├─ WebSocket / ActorContext
   ├─ RoomManager 与规则核心
   ├─ MySQL Repository
   └─ 受配额 Engine Supervisor
          │                 │
          ▼                 ▼
Managed MySQL      Pikafish / Jieqi / Rapfi
   │
   ├─ 自动时间点备份
   └─ 独立逻辑备份/恢复演练
```

首版约束：

- 单区域、单应用实例，避免在身份和房间尚未数据库化前制造跨实例状态问题。
- Redis、消息队列和对象存储不作为首版核心依赖；邮件首版在账号事务提交后投递，失败后通过受限重发恢复。
- 反向代理终止 TLS，Node 只接受来自可信代理/本机的生产流量。
- MySQL 不暴露公网端口，只允许应用和运维受控网络访问。
- 本地/LAN 启动方式不复用生产 Cookie、数据库或密钥。

Express 官方生产建议包括 TLS、可信输入边界、安全 Cookie、暴力破解防护和反向代理；参考 [Express production security](https://expressjs.com/en/advanced/best-practice-security/) 与 [performance and reliability](https://expressjs.com/en/advanced/best-practice-performance/)。

## 威胁清单与控制

### 账号接管与凭据攻击

| 威胁              | 主要控制                                                   | 验证                          |
| ----------------- | ---------------------------------------------------------- | ----------------------------- |
| 凭据填充/密码喷洒 | 邮箱+IP 和 IP 长窗口限流、统一错误、监控异常               | 多账号同 IP、单账号多 IP 测试 |
| 弱密码存储        | Argon2id、随机 salt、参数版本、禁止日志                    | 哈希格式测试、日志扫描        |
| 邮箱枚举          | 注册/登录/恢复统一外部响应和接近的处理路径                 | 存在/不存在账号响应比较       |
| 恢复链接被重放    | 高熵一次性 token、只存摘要、30 分钟过期                    | 并发使用只成功一次            |
| 会话固定          | 登录/重新认证后轮换 token                                  | 旧 token 立即失效             |
| 会话窃取          | 全程 TLS、`__Host-` HttpOnly Cookie、无 localStorage token | 浏览器存储和响应头检查        |
| 安全操作被劫持    | 当前凭据重新认证、CSRF、Origin 校验                        | 修改密码/删除账号 CSRF 测试   |

### 访问控制与 IDOR

| 威胁                     | 主要控制                                | 验证                        |
| ------------------------ | --------------------------------------- | --------------------------- |
| 修改 ID 读取他人私有资源 | ActorContext、owner 限定查询、404 隐藏  | A/B 全资源矩阵              |
| 客户端伪造 userId/role   | 忽略身份字段，连接绑定 actor            | HTTP/WS 注入测试            |
| owner 自动获得席位隐私   | owner 与 participant 分表/分判定        | 未落座 owner 揭棋测试       |
| 管理接口绕过             | 独立路由、数据库角色、权限和审计理由    | 普通 session 访问管理端测试 |
| 导出越权                 | 异步 job 绑定 owner、下载鉴权、短期链接 | B 猜 job/download ID        |

### WebSocket 与重放

| 威胁                | 主要控制                                           | 验证                  |
| ------------------- | -------------------------------------------------- | --------------------- |
| 跨站 WebSocket 劫持 | Upgrade Origin 白名单 + session + SameSite         | 恶意 Origin 拒绝      |
| 撤销后连接仍可写    | auth epoch、会话撤销通知/周期校验、关闭连接        | 退出/封禁后旧连接命令 |
| 重复落子/结算       | actor+match commandId 幂等、revision、事务         | 相同消息并发重放      |
| 跨房间消息          | 连接订阅 match 与消息 matchId 一致                 | 修改 roomId 测试      |
| 旧连接抢席          | 新连接接管时旧连接降权/关闭                        | 双设备并发命令        |
| 大消息阻塞          | maxPayload、schema/数量/深度上限、解析错误快速失败 | 畸形和边界载荷测试    |

### 匹配与对局一致性

| 威胁                     | 主要控制                                     | 验证                  |
| ------------------------ | -------------------------------------------- | --------------------- |
| 两人占同一席位           | MySQL 事务、行锁、可空生成列唯一键           | 并发 quick-match      |
| 用户同时多队列占位       | 用户范围唯一的有效队列记录/参与关系          | 多标签重复匹配        |
| 过期 revision 覆盖新状态 | 条件更新，冲突返回安全 snapshot              | 延迟消息测试          |
| 服务重启丢局             | match + participant + state 持久化，启动恢复 | playing 状态重启      |
| 断线计时漂移             | deadline 持久化，恢复时按服务端时间重建      | 断线期间重启          |
| 非法客户端局面           | 服务端规则核心从权威状态执行动作             | 伪造 moves/state 测试 |
| 删除账号留下占位         | 删除流程取消匹配/waiting，并权威结束 playing | 删除中账号对局测试    |

### 聊天与内容滥用

| 威胁          | 主要控制                                 | 验证                      |
| ------------- | ---------------------------------------- | ------------------------- |
| 刷屏/批量连接 | user/IP/match 多维限流和连接配额         | 洪峰测试                  |
| XSS           | React 文本渲染、服务端长度/字符策略、CSP | HTML/URL/Unicode 输入测试 |
| 冒充昵称      | author userId + 昵称快照由服务端生成     | 客户端 nickname 被忽略    |
| 禁言绕过      | userId 级禁言、匿名首版不可聊天          | 换 session/连接测试       |
| 删除逃避举报  | 删除状态与受限证据副本分离               | 删除后举报工单测试        |
| 日志泄露正文  | 结构化日志字段白名单                     | 日志扫描                  |

### 揭棋隐私

| 威胁                        | 主要控制                                   | 验证                         |
| --------------------------- | ------------------------------------------ | ---------------------------- |
| 通用 DTO 展开 referee state | 专用 Repository + 字段白名单投影           | 序列化字段扫描               |
| 客户端选择 audience         | audience 仅从 participant side 派生        | 修改 audience/includePrivate |
| 红方读黑方暗吃              | seat-specific projection                   | 双方暗吃逐帧比较             |
| 未来信息污染早期回放        | 公开事件正向重演、不可变帧                 | 所有 ply 快照比较            |
| 日志/错误泄露               | 禁止记录 state payload，错误只带 requestId | 故意触发校验错误并扫描       |
| 管理员误读                  | 常规 operator 不具 referee 权限            | 管理详情接口测试             |

### 引擎资源与拒绝服务

| 威胁                 | 主要控制                                 | 验证              |
| -------------------- | ---------------------------------------- | ----------------- |
| 大量分析耗尽 CPU     | 用户/IP 并发上限、全局队列、最长搜索时间 | 并发任务洪峰      |
| 过大 Threads/Hash    | 服务端硬上限，不信任客户端设置           | 边界参数测试      |
| 进程无限增长         | Engine Supervisor 总进程上限和空闲回收   | 连接风暴测试      |
| stop 干扰他人任务    | session/requestId/variant 精确绑定       | 跨连接 stop 测试  |
| 引擎崩溃拖垮真人对局 | 子进程隔离、失败熔断、真人规则不依赖引擎 | kill/无二进制测试 |
| 排位作弊辅助         | 排位/公网实战 scene 禁用分析和提示       | 协议绕过测试      |

### 数据库与备份

| 威胁             | 主要控制                                     | 验证                   |
| ---------------- | -------------------------------------------- | ---------------------- |
| SQL 注入         | 参数化查询、无字符串拼接标识符、最小 DB 权限 | 定向输入测试/代码检查  |
| 连接池耗尽       | 池上限、查询超时、事务 finally、ready 指标   | 慢查询和并发测试       |
| 半事务状态       | 明确事务边界、约束、幂等重试                 | 故障注入回滚           |
| migration 破坏   | 版本化前向 migration、备份、兼容发布顺序     | 上一 schema 升级和回滚 |
| 备份不可恢复     | 自动备份 + 定期独立恢复演练                  | 隔离环境恢复           |
| 生产数据进入开发 | 环境/凭据隔离、脱敏样例                      | 部署和访问审计         |

## HTTP 与浏览器安全基线

- 生产只接受 HTTPS/WSS；设置 HSTS 前先验证全部子域和证书策略。
- 使用安全响应头中间件并按 Canvas、音频、Worker 和资源加载实际需求制定 CSP。
- 关闭 `X-Powered-By`，统一 404/500 响应，不向客户端返回堆栈。
- CORS 默认不开；确需跨域时使用精确 origin 白名单并重新评审 Cookie/CSRF。
- 状态变更请求要求 JSON 内容类型、Origin 和 CSRF token。
- 静态资源指纹长期缓存，HTML/会话相关响应禁止错误共享缓存。
- 导入、导出、WebSocket 和普通 API 分别设置负载上限；现有 `10mb` 全局 JSON limit 需按路由收紧。
- 所有输入先验证类型、长度、数组数量、Unicode 长度、嵌套深度和业务语义。

## 可信代理与客户端 IP

- 生产 `trust proxy` 只能匹配明确代理数量或网段，不能无条件信任所有来源。
- 反向代理覆盖并清洗 `X-Forwarded-For/Proto/Host`，外部同名 header 不直接透传。
- 速率键使用解析后的可信客户端 IP；IP 只是风控信号，不是用户身份。
- 当前 `x-xiangqi-proxy-client-address` 仅用于本地 Vite/LAN 保护，不作为公网通用客户端 IP 方案。
- 本机 `/api/games` 的回环保护继续保留，直到公网 user game API 走独立路由和 actor。

## 秘密管理

### 秘密分类

- MySQL 应用、migration、backup 三类凭据。
- 会话/CSRF 相关 pepper 或密钥（若实现需要）。
- 邮件服务 API key、发件域配置。
- 监控、告警和对象存储凭据（对应功能启用时）。
- TLS 私钥由反向代理/证书系统管理，不注入前端构建。

### 规则

- 秘密不进入 Git、镜像层、前端环境变量、日志、测试快照或错误响应。
- 生产环境通过部署平台 secret store/文件挂载提供，启动时严格校验缺失值。
- 应用角色只拥有业务表所需 DML 权限，以及确有需要的受控例程执行权限。
- migration 角色拥有 schema 变更但不用于运行应用。
- backup 角色和存储凭据只给备份任务，不能被公网应用读取。
- 定义轮换手册：数据库密码、邮件 key 和会话相关密钥可独立轮换。
- 泄露演练至少覆盖撤销凭据、强制会话失效、审计影响和重新部署。

## 数据库备份与恢复

### 目标

- 首版产品目标：RPO 不超过 24 小时，RTO 不超过 4 小时。
- 托管 MySQL 开启自动备份/时间点恢复；具体窗口由选定服务验证。
- 每日额外生成加密逻辑备份，保留 7 份日备、4 份周备；备份目标与数据库故障域分离。
- 生产上线前完成一次完整恢复，之后至少每月恢复演练一次。

### 备份内容

- schema、migration 版本、生成列、检查约束、外键、索引和业务数据。
- 不备份运行中的原始 session Cookie；数据库中的 token hash 可随库备份但仍按敏感数据保护。
- 引擎二进制和权重不依赖数据库备份，由版本清单和发布制品重建。
- 部署配置只备份非秘密模板；秘密由 secret store 的独立恢复机制管理。

### 恢复验证

1. 在隔离网络创建空 MySQL database。
2. 使用与生产兼容的工具版本恢复。
3. 校验 migration version、表/索引/策略和应用角色权限。
4. 启动 staging 应用执行只读一致性检查。
5. 随机抽取用户私有文档做 schema 校验。
6. 恢复一盘 playing/finished 普通象棋、揭棋和五子棋对局。
7. 对揭棋生成 red/black/public 投影并比较固定语料。
8. 确认旧 session 的恢复策略：灾难恢复后默认增加全局 session epoch 或批量撤销，避免备份中的旧会话意外复活。

### 失败处理

- 备份任务失败立即告警，不以“上次成功”掩盖连续失败。
- 未验证可恢复的备份不计入可用备份。
- migration 前创建可验证恢复点；回滚应用时不执行破坏性 down migration。
- 恢复后先只读验证，再开放写流量和 WebSocket。

## 可观测性基线

### 结构化日志字段

- `timestamp/level/event/requestId/connectionId/matchId/route/status/durationMs`。
- userId 只在访问控制和安全事件需要时记录内部不可公开值。
- IP 使用受控保留或前缀化字段；不记录密码、token、邮箱全文、聊天正文或棋局 payload。
- 错误对外只返回稳定 code + requestId，内部日志保留经过清洗的错误类别。

### 指标

- HTTP：请求量、状态、延迟、限流、连接池等待。
- 认证：注册、验证、登录成功/失败、恢复、会话撤销；标签不得使用原始邮箱。
- WebSocket：活跃连接、Upgrade 拒绝、重连、心跳超时、每 scene 连接数。
- 匹配/对局：等待时长、匹配成功、活跃 match、异常终局、revision 冲突。
- 数据库：连接、查询延迟、事务回滚、deadlock、migration 和备份结果。
- 引擎：进程数、队列、搜索耗时、超时、崩溃、任务拒绝和资源上限。

### 健康检查

- `/health/live`：事件循环仍工作，不访问依赖。
- `/health/ready`：配置有效、数据库可执行轻量查询、必要 schema 版本匹配。
- 引擎状态单独暴露；引擎不可用不必让真人在线规则服务整体 unready，但分析入口要降级。
- 健康响应不返回版本细节、主机路径、数据库地址或秘密。

## 容量与配额初始值

实现前以压测校准，首版默认上限作为安全起点：

- 每账号最多 2 个排队/活跃公网棋手连接，10 个总 WebSocket 连接。
- 每 IP 最多 30 个总 WebSocket，代理/NAT 场景通过观测调整。
- 每账号最多 3 个 waiting/playing match。
- 每 match 最多 50 个登录观众，沿用当前局域网上限。
- 聊天沿用当前内容 200 字符、历史 100 条显示窗口，并增加账号/IP 频率限制。
- 引擎任务按用户最多 1 个有限搜索 + 1 个交互任务，全局进程/线程/Hash 由主机容量硬限制。
- 导入/导出、研究 payload 和节点数量继续沿用现有各模块校验，不扩大到全局 10MB 默认。

这些是配置和门禁，不是性能承诺。压测后只能在资源和告警同步更新时提高。

## 发布与回滚

### 环境

- `development`：本地 MySQL/测试邮箱，不接触生产 secret。
- `test`：独立 database，自动清理，禁止连接非测试 host。
- `staging`：与生产同拓扑的小规模资源、独立账号和密钥。
- `production`：只通过受控发布，禁止应用启动时自动猜测 migration。

### 发布顺序

1. 检查工作树、构建、测试和 migration dry-run。
2. 验证最近备份与恢复点。
3. 先部署向后兼容 schema 扩展。
4. 部署兼容旧/新 schema 的应用。
5. staging/灰度账号执行注册、登录、匹配、三棋类对局和恢复。
6. 观察错误、DB、WS 和引擎指标。
7. 切换功能开关扩大范围。
8. 破坏性清理留到后续独立发布。

### 回滚

- 公网在线入口有服务端开关，关闭不影响本地和 LAN 模式。
- 回滚应用不自动执行 down migration。
- 进行中公网对局关闭新匹配后允许已有对局在兼容窗口内完成；紧急情况按明确异常终止原因结算。
- 协议至少兼容前一部署版本或强制安全刷新并拒绝旧写消息。
- 发生数据完整性风险时先转只读/关闭写入口，再恢复或补偿，不尝试静默继续。

## 第零批完成门禁

- 账号与会话设计、数据模型、访问矩阵和本文互相引用且无身份边界冲突。
- MySQL、单实例、无 Redis、LAN 隔离和一局一 ID 已作为首版正式决策。
- 账号、共享对局、聊天、揭棋和安全事件的默认保留/删除策略明确。
- 账号接管、IDOR、WS 重放、匹配并发、聊天、引擎 DoS、揭棋泄露和备份风险均有控制与测试入口。
- 第一批可以直接依据文档建立 migration/Repository，不需要再猜首版身份和表边界。
- 实际公网发布仍需完成后续 P0 实现、测试、恢复演练和适用规则复核；完成设计不代表已经可上线。

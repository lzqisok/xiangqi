# 公网排位等级分策略

本批开放带服务端权威棋钟的快速排位，并为后续按分差匹配提供可信等级分事实来源。已实现结算、公平规则及本人积分查询；按等待时间扩大分差、排行榜和赛季重置仍属于后续批次。

## 模型与分池

- 采用 `elo-v1`，初始分 1500；双方任一账号未完成 10 局时，本局统一使用 K=40，之后使用 K=24。统一 K 值保证单局变动零和。
- 首版不设赛季，结算记录保留模型名，未来如启用赛季必须新增赛季标识和迁移策略，不能覆盖历史流水。
- 分池固定为普通象棋、揭棋、自由规则五子棋、禁手规则五子棋四类。不同玩法或五子棋规则的结果不能相互影响。
- 等级分最低为 100。当前账号可通过 `GET /api/me/ratings` 读取各已参与分池的分数、对局数、胜和负及暂定状态。

## 结算资格

同时满足以下条件才结算：

1. 对局由快速匹配创建，`competition_mode = rated`；
2. 使用 `10m`、`15m-10s` 或 `30m` 服务端权威棋钟；
3. 双方席位均绑定不同的有效账号；
4. 已进入对局阶段（`started_at` 非空），以将死、困毙、认输、协议和棋、重复、自然限着、步数上限、成五、禁手、满盘、超时或单方断线判负结束。

好友/邀请房、休闲匹配、无棋钟对局、未开局、双方放弃及管理员作废不计分。客户端提交的分数或胜负不参与计算，终局状态只来自服务端规则和事务。

## 原子性、幂等与审计

终局更新、等级分行锁、双方分数与胜和负计数、`match_rating_settlements` 结算快照和 `rating_ledger` 流水在同一数据库事务完成。每个 `match_id` 最多存在一条结算；重复命令和事务重试不会重复加减分。

结算记录保存双方账号、分池、结果、K 值和变更前后分数。管理员作废通过 Repository 补偿事务反向应用原结算差值、回退双方计数、写入两条 `void` 流水并记录原因；重复作废是无操作。该能力目前不暴露给普通用户接口，后续管理后台必须沿独立权限与审计链路调用。

## 断线与公平竞赛（B 第一子批）

- 快速匹配进入 `playing` 即视为开局，不以第一手落子为资格门槛；零走子时单方断线超过宽限同样判负并正常扣分，防止通过不落子逃分。
- 裁决时只有一方宽限到期，按该方负局计分；双方断线宽限均已到期则以 `abandoned` 和局结束，不计分。短暂同时离线但只有一方宽限到期不适用放弃规则。
- 服务故障或管理员中止不计分，按下方中止规则执行。已误结算的对局由积分作废补偿纠正。
- 断线终局与积分、流水处于同一事务；写入失败必须回滚终局，由既有恢复任务重试。重复裁决不得重复结算。
- 三棋类排位均禁止申请或同意悔棋；升级前遗留申请仍可拒绝、撤回或到期，不能接受。休闲协商规则保持原样。
- 排位禁止使用引擎辅助。这是竞赛规则，不代表可以阻止外部设备或外部引擎作弊；账号跨连接辅助限制已覆盖两类服务端引擎连接。

当前修改只影响后续终局，不自动重算历史断线对局。

协议错误：排位 `match-propose` 的 `undo` 及 `match-proposal-respond` 接受旧悔棋申请返回 `rated_undo_forbidden`（409，排位对局禁止悔棋）；无新增字段或数据库迁移。

## 匹配防滥用（B 第二子批）

- 同一分池、同一对账号在最近 24 小时内最多通过快速排位匹配开局 3 次。红黑互换和切换棋钟不重置次数；普通象棋、揭棋、五子棋自由/禁手规则分别计数。已开局未结束、双方放弃和后来作废的对局也占用次数，避免通过延迟结算或异常终局绕过限制。
- 达到上限后跳过该对手，继续选择其他合格候选；没有合格候选则正常排队，受原有 5 分钟队列有效期约束。休闲、邀请和再来一局入口不产生新的排位积分资格。该限制减少重复对手刷分，不代表可识别多账号串通。
- 首次成功取消开启一个 10 分钟计数窗口（不是滑动窗口）；同一窗口内第 5 次成功取消后，未来 10 分钟暂停该账号的新快速匹配，覆盖休闲、排位、棋类、会话与设备。取消本身始终可以完成；空队列重复取消、配对已经完成后的取消不增加计数。冷却到期后新窗口重新计数。
- 匹配与取消均在数据库事务内按账号及现有匹配容量锁串行化。并发多标签页保持账号唯一队列；已有排队请求切换条件仍返回原队列，需要显式取消后重新选择。已处理的 requestKey 重放返回原结果，不占新队列。
- `POST /api/online/quick-match` 在冷却期返回 HTTP 429、`error: matchmaking_cooldown`、`retryAfter` 秒数及 `Retry-After` 响应头，客户端展示等待秒数。重复对手保护不返回错误，仍返回普通等待状态；客户端规则说明提示可能需要等待其他对手。
- 指标 `xiangqi_matchmaking_protection_total` 使用固定 `reason`：`repeat_opponent_wait` 表示本次未找到合格候选但存在同条件对手，`cancellation_cooldown` 表示新匹配被冷却拒绝。`xiangqi_matchmaking_cancellations_total` 使用 `result=cancelled|noop`。保护指标记录尝试，可包含随后回滚的事务，不作为计分或审计事实；不记录账号 ID 标签。

需先执行迁移 `0008_matchmaking_fairness.sql`。取消状态每账号最多一行，随账号硬删除级联清理；进程重启不清空。重复对手次数读取持久化对局和参与关系，后续对局保留/清理任务必须保留至少 24 小时内的这些事实，或先迁移独立防滥用记录。当前不新增历史自动清理。

参数固定在 `server/src/online/matchmakingPolicy.ts`；尚未根据真实 staging 流量调优，低流量环境达到同对手上限后可能较难匹配。

## 服务故障与管理员中止

- 服务启动完成 schema 校验后、监听请求前，将仍在进行的排位以 `service_restart` 中止，不结算积分。有计划重启应先摘流并等待排位结束。休闲对局沿用恢复机制；该规则替代旧版排位重启后继续计钟的策略。
- 自动超时/断线裁决收到 `DatabaseUnavailableError` 时，记录待中止状态；数据库恢复后的重试优先以 `service_failure` 中止受影响排位，不重试扣分裁决。期间玩家新命令也先处理该待中止状态。若进程同时退出，由启动中止流程承接。普通 SQL 事务错误仍回滚重试，不能一律视为网络服务故障。
- 该识别范围是服务端实际观测到的数据库不可用和进程重启；未被观测的网关或网络故障需运维核实，客户端不能自报故障免扣分。
- 运维命令 `pnpm --filter server online:interrupt <matchId> <operator> <reason>` 通过本机数据库凭据执行 `admin_abort`，要求操作者和原因非空，写入 `match_interruptions`。普通账号 HTTP/WS 不提供中止入口。中止同事务停止棋钟、结束对局并清理待协商；重复执行无副作用，与超时/走子共用对局锁。若正常终局先完成，命令返回 `interrupted=false`，必要时另行复核积分作废补偿。
- 中止对外仍使用兼容的 `finished/draw/abandoned` 状态，本人积分明细提供具体未计分原因。运行中 CLI 中止由补偿扫描同步至订阅者，默认最多约 30 秒；期间服务端已拒绝新走子。

## 账号级辅助限制

`/ws`（普通象棋/揭棋）与 `/gomoku-ws`（五子棋）在启动引擎请求前、发送分析/候选/提示结果前查询账号是否有任一棋类 `playing/rated` 对局。新连接、其他会话、跨设备和先分析后进入排位均适用；数据库查询失败也拒绝输出。进行中的流式分析被拒绝后停止；`stop` 保持可用。原公网订阅连接限制保留。没有排位的账号和本地/LAN 匿名玩法继续可用；无法阻止外部设备、外部引擎或另一个账号作弊。

## 本人积分查询

- `GET /api/me/ratings/matches/:id`：返回 `matchId/state/reason/before/after/delta/voidReason`。未结算数值为 null，状态为 `pending|settled|voided|unrated`；只有参与账号能读取，其他账号 404。历史未结算且原因无法精确重建时显示 `ineligible_or_legacy`，不伪造分数。
- `GET /api/me/ratings/ledger?limit=20&cursor=<id>`：返回 `entries/nextCursor`，limit 为 1～100 整数。按时间与 ID 降序，游标限定本人，保留微秒排序精度。每条包含本人的分池、原分、现分、变动、结算或作废类型、原因与时间；不接受查询参数指定其他账号。
- 作废明细保留原结算前后值并明确标注已作废，补偿在单独流水中展示；前端可以加载更多、刷新及失败重试，账号变更后重置数据并忽略旧响应。本局积分仅对参与者展示。
- 本批最高 migration 为 `0009_match_interruptions.sql`，没有普通用户积分写入接口。历史自动重算、排行榜和管理后台不在 B 范围。

# 公网排位等级分策略

本批开放带服务端权威棋钟的快速排位，并为后续按分差匹配提供可信等级分事实来源。首版只实现结算闭环；按等待时间扩大分差、排行榜和赛季重置仍属于后续批次。

## 模型与分池

- 采用 `elo-v1`，初始分 1500；双方任一账号未完成 10 局时，本局统一使用 K=40，之后使用 K=24。统一 K 值保证单局变动零和。
- 首版不设赛季，结算记录保留模型名，未来如启用赛季必须新增赛季标识和迁移策略，不能覆盖历史流水。
- 分池固定为普通象棋、揭棋、自由规则五子棋、禁手规则五子棋四类。不同玩法或五子棋规则的结果不能相互影响。
- 等级分最低为 100。当前账号可通过 `GET /api/me/ratings` 读取各已参与分池的分数、对局数、胜和负及暂定状态。

## 结算资格

同时满足以下条件才结算：

1. 对局由快速匹配创建，`competition_mode = rated`；
2. 使用 `10m`、`15m-10s` 或 `30m` 服务端权威棋钟；
3. 双方席位均绑定不同的有效账号；
4. 以将死、困毙、认输、协议和棋、重复、自然限着、步数上限、成五、禁手、满盘或超时正常结束。

好友/邀请房、休闲匹配、无棋钟对局、掉线判负、双方放弃及管理员作废不计分。客户端提交的分数或胜负不参与计算，终局状态只来自服务端规则和事务。

## 原子性、幂等与审计

终局更新、等级分行锁、双方分数与胜和负计数、`match_rating_settlements` 结算快照和 `rating_ledger` 流水在同一数据库事务完成。每个 `match_id` 最多存在一条结算；重复命令和事务重试不会重复加减分。

结算记录保存双方账号、分池、结果、K 值和变更前后分数。管理员作废通过 Repository 补偿事务反向应用原结算差值、回退双方计数、写入两条 `void` 流水并记录原因；重复作废是无操作。该能力目前不暴露给普通用户接口，后续管理后台必须沿独立权限与审计链路调用。

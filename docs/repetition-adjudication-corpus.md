# 长将与长捉裁定语料设计

## 规则基线

本项目以中国象棋协会审定的《象棋竞赛规则（2020 版）》为首版规则基线：循环反复三次形成重复局面，单方长将立即判负；其他待判局面需要继续按照将、杀、捉、闲以及责任方关系分类。规则还明确规定帅（将）、兵（卒）本身允许长捉，并对无根子、车、联合捉、邀兑、献子和子力交换作了不同处理。

- 规则目录：<https://cnchess.net/rules/rules2020.html>
- 第 23 条“待判局面的裁定”：<https://cnchess.net/rules/ChapterFiveSection23.html>
- 第 24 条“术语解释”：<https://cnchess.net/rules/ChapterSixSection24.html>
- 第 26 条“棋例通则”：<https://cnchess.net/rules/ChapterSixSection26.html>

## 可执行语料格式

每个案例由合法起始 FEN、线性 UCI 着法和预期分类组成。测试必须先用现有走法引擎完整重放，排除仅在文本层成立但棋盘上非法的伪案例。

当前语料已固定在 `client/src/engine/repetitionAdjudication.test.ts`，并由 `client/src/lan/ruleParity.test.ts` 对客户端与局域网权威端执行一致性校验：

| 案例         | 起始方 | 循环特征                   | 当前预期               |
| ------------ | ------ | -------------------------- | ---------------------- |
| 单方连续长将 | 黑     | 红方每个循环着法均将军     | 红方责任，黑胜         |
| 单方连续长捉 | 红     | 红车逐着追捉同一黑车       | 红方责任，黑胜         |
| 帅将长捉例外 | 红     | 红帅逐着追捉同一黑炮       | 允许着法，重复作和     |
| 一将一捉     | 红     | 红炮交替将军、追捉同一黑车 | 红方责任，黑胜         |
| 四次重复     | 红     | 双方闲着形成三个完整循环   | 只分析最近两个完整循环 |
| 不足三次重复 | 黑     | 仅回到同局面一次           | 不进入待判             |

## 分阶段落地边界

当前 `analyzeRepetitionCase` 与 `adjudicateRoomRepetition` 只提供裁定证据，不接入 `getAutomaticDrawReason` 或局域网服务端终局裁定。因此现有“三次重复自动和棋”行为暂时不变，不会因尚未覆盖的长捉细则产生新的误判。

后续在替换简化裁定前，至少需要补齐以下固定案例：

1. 单方捉与联合捉的责任方差异。
2. 有根子、假根、邀兑、献兼捉、等值与不等值交换。
3. 外来点首着、首着吃子扣除和三个以上点的九回合特例。
4. 上述语料在客户端本地与服务端局域网继续保持完全相同的结果。

只有上述案例经规则条款逐一审阅后，才新增“责任方判负”状态并替换当前简化裁定。

# 长将与长捉裁定语料设计

## 规则基线

本项目以中国象棋协会审定的《象棋竞赛规则（2020 版）》为首版规则基线：循环反复三次形成重复局面，单方长将立即判负；其他待判局面需要继续按照将、杀、捉、闲以及责任方关系分类。规则还明确规定帅（将）、兵（卒）本身允许长捉，并对无根子、车、联合捉、邀兑、献子和子力交换作了不同处理。

- 规则目录：<https://cnchess.net/rules/rules2020.html>
- 第 23 条“待判局面的裁定”：<https://cnchess.net/rules/ChapterFiveSection23.html>
- 第 24 条“术语解释”：<https://cnchess.net/rules/ChapterSixSection24.html>
- 第 26 条“棋例通则”：<https://cnchess.net/rules/ChapterSixSection26.html>

## 可执行语料格式

每个案例由合法起始 FEN、线性 UCI 着法和预期分类组成。测试必须先用现有走法引擎完整重放，排除仅在文本层成立但棋盘上非法的伪案例。

当前语料已固定在 `client/src/engine/repetitionAdjudication.test.ts`，并由 `client/src/lan/ruleParity.test.ts` 对客户端与局域网权威端执行一致性校验：

| 案例             | 循环特征                                     | 当前预期                   |
| ---------------- | -------------------------------------------- | -------------------------- |
| 单方连续长将     | 一方每个循环着法均将军                       | 责任方负                   |
| 单方连续长捉     | 炮隔子连续追捉同一车                         | 责任方负                   |
| 同兵种邀兑       | 车对车接触且被邀兑方接受后不受损             | 按闲处理，重复作和         |
| 献兼捉           | 进攻炮自身可被吃，同时形成净得子的追捉       | 从重按捉，责任方负         |
| 帅、兵自身长捉   | 帅或过河兵仅以自身直接追捉                   | 允许着法，重复作和         |
| 帅应将附带捉     | 帅每次应将后附带产生攻击                     | 按闲处理                   |
| 帅走后其他子新捉 | 帅并非自身攻击者，而是走后让其他子产生新攻击 | 按捉处理                   |
| 真根与等值交换   | 被捉子可合法反吃，完整互吃无净收益           | 按闲处理                   |
| 假根             | 形式保护子受牵制，离线反吃会暴露己方将帅     | 假根无效，按捉处理         |
| 单捉对联合捉     | 一方直接捉无根子，另一方净得子依赖炮架接应   | 单捉方责任，联合捉方可不变 |
| 一将一捉         | 同一方在循环内交替将军和追捉                 | 责任方负                   |
| 四次重复         | 同一局面出现四次                             | 只分析最近两个完整循环     |
| 不足三次重复     | 当前局面只出现两次                           | 不进入裁定                 |

## 裁定实现

客户端 `analyzeRepetitionCase` 与服务端 `adjudicateRoomRepetition` 都按稳定棋子身份分析最近两个完整循环。每着先判“将”；非将着再计算走后新产生的物质威胁，并检查对方应着是否避开原攻击来源。

“捉”不是简单的攻击格判断。裁定器会沿目标格枚举双方所有合法互吃，计算完整交换后的最佳净收益：

- 被牵制且无法合法反吃的根自动按假根处理。
- 等值或得不偿失的完整交换不算捉。
- 同兵种可安全互吃按邀兑处理。
- 走子自身送吃但同时存在净得子威胁，仍从重按捉。
- 走子造成其他子新攻击仍按捉处理；若完成净得子必须依赖另一个己方参与子（例如炮架或互吃中的接应子），记为联合捉，否则记为单捉。

普通象棋本地对局通过 `getAutomaticGameStatus` 使用该结果；局域网房间由服务端在 `executeRoomMoveFromState` 中权威裁定。普通重复判和，只有一方使用禁止着法时判责任方负；双方均为禁止着法时按第 26.9 条比较长将优先级及单捉/联合捉责任。揭棋不进入这一裁定器。

## 产品化边界

竞赛规则第 23 条包含“棋手提出裁决”和非长将情形允许变着的现场裁判程序。应用没有裁判申请阶段，因此采用确定性的数字对局策略：普通象棋一旦形成三次重复便自动审核最近两个循环并给出终局结果，不额外模拟线下裁判的申请与两回合口头告知流程。

第 23.4 条“三个或三个以上点、九个回合但尚未形成三次重复”的情形同样要求一方提出；当前自动裁定只处理可由局面键客观确认的三次重复，不对未提出的非重复攻击序列主动结束对局。这一程序差异不影响三次重复下的将、捉、闲和责任分类。
